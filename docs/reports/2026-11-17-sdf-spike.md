# SDF text: spike and opt-in implementation

## Phase 1 implementation

Smooth Scaling (SDF) is off by default. The `_sdf` IDs are runtime aliases of the loaded raster
definitions, not a second generated inventory. The 8 px compact, 9 px regular/heading, 11 px
title and 20 px fixed wordmark share one 64 pixels-per-em strike per TTF. Real weights and italics
follow the raster providers (including the existing synthetic slant and single-weight exceptions).
Minecraft fallback glyphs and icons remain bitmap. World-space text remains bitmap; this change
does not port distance fields to world depth, lightmap, see-through or OIT pipelines.

1. **Spacing:** pass the original raster `GlyphInfo` through unchanged, with fractional pen positions
   from Minecraft. Use the raster bitmap's bearings and ink bounds, never advances from the 64 px strike.
2. **Stray marks:** FreeType bitmap SDF adds an 8-texel spread, then Aurora adds a zero-byte border
   one texel wide. For each axis, expand the raster ink quad by `9 × logicalInkSize / strikeInkTexels`
   on each side. UVs are `(cellStart + 0.5) / 256` through `(cellEnd - 0.5) / 256`, clamped to `[0,1]`,
   and sampled with LINEAR clamp. The probe now wraps both columns to the narrower measured width.
3. **Weight:** decode `d = (255 × sample - 128) × 8 / 128` in strike texels. Coverage is
   `clamp(0.5 + (d - 0.30) / max(fwidth(d), 0.0001), 0, 1)`. The positive inward bias reduces
   coverage at the original edge without fixing the derivative width to one pose scale.

The SDF atlas is capped at 128 shared 256² R8 pages (8 MiB of texture payload, excluding driver
overhead, normal raster/fallback pages and lazily opened font files). No CPU cell bitmap is retained.
There is no eviction during a font-manager lifetime. Cold glyph work is attempted only on draw;
after 2 ms of measured cold work in a frame, uncached glyphs draw raster until a later frame.
This is a soft limit: one glyph or face open may run past it. A cold alias's vanilla provider scan
and first shader compile are separate costs. Cached glyphs generate no new atlas work or extra quad
relative to the matching bitmap glyph. HUD Full keeps its existing offset draws.

The adapters compile-check the GUI pipeline at first use using Blaze3D (26.1.2/26.2) or RenderPearl
(26.3). Shader imports and vertex varyings follow each native line. Compilation, alias initialization
or atlas upload errors disable SDF for the session; missing/oversized glyphs and page-cap overflow
fall back individually. ModernUI and Caxton stand down all SDF mixins. GUI-scale changes refresh
the raster metrics without rebuilding the distance-field cells, while resource reload retires the pages.

### Phase 1 acceptance

- Compare `sdf-compare 1`, `2`, and `3` on 26.1.2 OpenGL/VulkanMod and 26.2/26.3 OpenGL/native
  Vulkan. Wait for the specimen to warm, widen the viewport or use smaller GUI scale to fit all rows,
  and confirm zero width deltas, no gaps or stray pixels, comparable 1× weight and smoother large text.
- Compare module/detail windows, tooltips, Pulsar and the title wordmark with SDF off/on; include compact
  and title roles, a real italic, a synthetic slant, a missing-glyph fallback and a GUI-scale change.
- Check a vanilla screen, chat, scoreboard and HUD (including HUD editor previews) under Off, Aurora UI
  Only and All Text. Confirm existing wrapping and centring, plus raster fallback under ModernUI/Caxton
  and with an SDF shader deliberately unavailable in a disposable fixture.
- Record cold-start hitching and settled overhead against ADR 0005. The Java CPU microbenchmark excludes
  atlas upload, shader compile and frame scheduling; native GPU and optical acceptance are still pending.

## Phase 0 spike

2026-11-17. Developer flag only (`-Daurora.text.sdf=true`), Minecraft 26.3, OpenGL, Inter Medium.
FreeType `FT_RENDER_MODE_SDF` glyphs in an isolated linear-sampled R8 atlas, drawn through
`aurora:pipeline/gui_text_sdf` on Minecraft's normal text path; raster fallback on any failure.
Comparison: parity probe `sdf-compare <scale>`.

## Findings (in-client, GUI scale 3)

- The pipeline works end to end: glyphs generate, upload and draw; 94 mixins applied; no
  fallback was logged.
- Scaled text is the clear win: at pose scale 3 the raster column is blocky (nearest-sampled
  8x upscale) while SDF stays smooth ([3x](evidence/sdf-spike/sdf-3.png)).
- Bug 1, spacing: SDF glyphs land at uneven positions ("Cas e", "jum ps", "laz y" at 1x;
  [zoom](evidence/sdf-spike/sdf-1-zoom.png)). Advances or bearings are rounded per glyph.
- Bug 2, stray marks: small fragments from neighbouring atlas cells appear beside some glyphs
  ([zoom](evidence/sdf-spike/sdf-3-zoom.png)), also visible on window text with the flag on
  ([window](evidence/sdf-spike/sdf-window-crop.png)). Likely insufficient atlas padding for linear
  sampling or quads extending past the glyph's padded cell.
- At 1x, SDF text reads slightly heavier than the exact-size raster.

Not production-ready; flag off is unchanged (tests green on all three lines).
