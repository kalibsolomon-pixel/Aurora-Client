Branch `port/26.2`, stacked on `port/26.1` (PR #10). Roadmap step 4, second checkpoint. The release target remains 26.3; this checkpoint is not a production release.

## Changes

- GUI ownership moved to `Minecraft.gui`: screens, overlays, toasts and HUD. HUD mixins now target `Hud`; camera and main target accessors follow the new names.
- Held-item submission, fire overlay, shield model and name-label signatures are retargeted. Shield atlas entries now let vanilla supply its relocated shield sprites and only add Aurora's white overlay sprite.
- Render pipelines use 26.2's vertex bindings, topology, bind group layouts, GPU formats and render-pass signatures.
- Glass uses the existing `PortableBlurRenderer` on every backend. The raw OpenGL path and synthetic-backdrop implementation were removed. Deferred captures still run after the world/panorama and before GUI drawing, with per-panel sampling, pooled outputs, next-frame resource retirement, the 400 ms screenshot interlock and one opacity application. Deferred CPU submission is included in `Timed`. No renderer or visual feature was added.
- World overlays use Minecraft's staged vertex buffers and prepared render types. In 26.2 `BEFORE_BLOCK_OUTLINE` runs during submission collection: drawing there was covered by terrain. It now selects the state; the timed draw runs after translucent features. Hitboxes and waypoints keep that draw phase. Owned world/glass buffers close at client shutdown.
- Vanilla 26.2 builds the base item geometry before its foil pass. Removed the obsolete glint-ordering buffer wrapper, two mixins/accessors and their three wrapper tests. Alternative Glint still uses Aurora's masked pipelines.
- The VSync override changes the surface's requested present mode and invalidates its configuration when the override changes. The saved vanilla VSync preference is preserved.
- Automatic GPU pacing uses native query pools and a guarded clock accessor. Calibration runs once per device: Vulkan's current-timestamp call submits and waits, so doing it per frame would stall rendering. Each pair's duration comes directly from its GPU timestamps.
- Diagnostics name the actual native backend. `-Paurora.runDir=...` selects a disposable Loom game directory. The matrix runner accepts a directory, backend and report count, passes spaced world names through JavaExec arguments, verifies the reported backend and removes only its staged jars.

## Verification (2026-11-11)

- `gradlew build` succeeds: 648 tests pass, one is skipped (649 discovered); all 72 remaining mixins apply on OpenGL and native Vulkan. The static mixin target checker reports zero problems, including optional targets.
- Final factory Aurora defaults on OpenGL, including the corrected block-overlay draw: six diagnostics reports, four judged after two warm-ups, 0.217?0.228 ms mean and 0.340?0.390 ms p95. The release overhead check passes. See [MOD_MATRIX.md](../MOD_MATRIX.md).
- Final factory-default native Vulkan baseline, with the corrected block overlay: 0.152?0.176 ms mean and 0.186?0.233 ms p95 in runs 3?6; `overhead_check.py` passes.
- Native Vulkan boots into the copied world and renders Aurora's real no-world title panorama, menu settings and in-world glass. In a runtime probe, the VSync override changes `FIFO_RELAXED` to `IMMEDIATE` and back while vanilla's saved preference stays true; automatic GPU timing remains active and reports samples.
- Screenshots inspected at 854?480 and 1598?892: module grid/list, Dark theme, live SQUARE/19% and factory ROUND/33% appearance. Fonts, Material Symbols, centered labels, HUD, the pig hitbox, shield status overlay and Alternative Glint were exercised. The block-overlay screenshot was compared with vanilla after fixing the draw phase.
- Available 26.2 matrix: performance stack passes on OpenGL and Vulkan; Sodium + Iris passes on OpenGL. Forcing Vulkan with Iris 1.11.4 aborts in Iris's OpenGL sampler initialization before diagnostics; this combination is recorded as failing, not supported. Minecraft 26.2 supplies native Vulkan and Sodium supports it, replacing the old VulkanMod row.

Runtime evidence lives under the ignored `build/port-26.2/` fixture; no probe mod is shipped. Tests use a disposable upgraded world. An early launch exposed that overriding JavaExec's working directory was superseded by Loom; it reached only the live world's upgrade prompt. The backed-up live config/options were restored byte-for-byte, and the live world was unchanged. All subsequent launches use the explicit Loom run-directory property.

## Limits and next checkpoint

This is build/boot, targeted rendering and compatibility evidence on Windows 11 with an RX 9070 XT. It does not verify multiplayer, shader packs, a production launcher, held-key FreeLook/zoom, damage tilt, armor trims or every HUD/layout state. Iris on forced Vulkan is a known external failure; its native stack is in the matrix console log and reproduces with Aurora disabled.

Next: 26.3. SDL replaces GLFW; migrate saved keyboard/mouse codes and adapt frame pacing, click counting and text-input focus before release. Ports and version-adapter extraction remain roadmap step 5.
