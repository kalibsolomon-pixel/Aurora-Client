# Port to Minecraft 26.1

Branch `port/26.1`, stacked on the pre-port checks (#9). Roadmap step 4, first checkpoint: make 26.1 build and boot (ADR 0002).

**State (2026-11-11):** compiles, all 652 tests pass, all 72 mixins apply, and the dev client boots into the saved world and shuts down normally. The overhead budget passes on 26.1 (runs 3 to 6: 0.147 to 0.165 ms Aurora CPU per frame, against 0.148 to 0.179 on 1.21.11). Not yet checked by eye in game: see the last section.

26.1 is the first unobfuscated release: no mappings line, `modImplementation` becomes `implementation`, the mixin refmap is gone ([Fabric for Minecraft 26.1](https://fabricmc.net/2026/03/14/261.html)).

## Done so far

- Build, `fabric.mod.json` (`~26.1.2`, Java 25) and `aurora.mixins.json` (no refmap, `JAVA_25`).
- `GuiGraphics` is `GuiGraphicsExtractor` in 26.1 (96 files).
- Its methods were renamed where javac reported them, never by blanket text replace, because Aurora has its own `drawString` helpers: `drawString`/`drawCenteredString` to `text`/`centeredText`, `renderItem` to `item`, `hLine`/`vLine` to `horizontalLine`/`verticalLine`, and so on. Screen and widget entry points follow: `render` to `extractRenderState`, `renderBackground` to `extractBackground`, `renderWidget` to `extractWidgetRenderState`. 168 call sites and declarations.
- Compile errors: 543 at first (most hidden behind the missing class), then 72, now none.
- Fabric API renames applied (table below). HUD layers are `HudElementRegistry.addLast` in the old registration order (`waypoint_labels`, `hud_modules`, `alerts`, `hitreg_score`), still timed by `Timed.hud`. Hitboxes and waypoints moved to `AFTER_TRANSLUCENT_FEATURES`, the event Fabric documents as after entity and block-entity geometry is drawn, the closest to the old `AFTER_ENTITIES`.
- Minecraft API changes: `ChunkPos` is a record (`x()`, `pack`); block tints come from `BlockColors.getTintSource(...).colorInWorld`; `OptionsScreen` takes `inWorld`; tooltip and button overrides are `extractImage`/`extractContents`; `BakedQuad`'s tint flag and sprite live in `materialInfo()`; shield sprites are `SpriteId`/`SpriteGetter` and `submit` lost its `ItemDisplayContext`; pipelines take `DepthStencilState`/`ColorTargetState` records (no depth state means no depth test, as vanilla's GUI pipelines); armor cutout is `entityCutoutZOffset` (no-cull is now the default; `entityCutoutCull` is the culling one); the trim decal uses `ARMOR_DECAL_CUTOUT_NO_CULL`, which vanilla now builds with the overlay.
- Glass backend detection reads `GpuDevice.getBackendName()` (`"OpenGL"`); `GlDevice` is no longer public.
- Source-contract tests that matched old names were updated, including three `assertFalse` checks that could no longer fail.
- **Fail-soft fix found here** (separate commit): with `require = 1`, an `@At` that matched nothing threw an `Error` Mixin treats as fatal, so the first boot crashed at launch. `InjectionCheck` now reports such mixins after they apply, and `defaultRequire` is 0.

## Needed judgment (now done; check in game)

- **Glass backend detection.** `RenderBackend` checks for `GlDevice`, which is no longer public. Glass must still pick the OpenGL or portable path correctly, and 26.2 asks every mod to stop calling OpenGL directly.
- **Hitbox and waypoint world rendering** hooked `AFTER_ENTITIES`, which no longer exists. The replacement event decides draw order against entities; check in game.
- **HUD registration** moves from a callback list to named `HudElementRegistry` layers; Aurora's HUD, waypoint labels, alerts and Better Hitreg's score each need a layer, still timed for the overhead budget.
- Render pipeline and model changes: `RenderPipeline` depth flags (glint), `BakedQuad` (item sprites), `Material`/`MaterialSet` (shield), `RenderTypes` (armor trims), `CameraRenderState`, `ChunkPos` accessors, `BlockColors.getColor`.

## Later versions, from Fabric's posts

- 26.2: raw OpenGL calls must move to Blaze3D; `Minecraft.setScreen` and other GUI methods move to `gui`. Loom 1.17, Gradle 9.5.1.
- 26.3: SDL replaces GLFW. Aurora stores keybinds as raw GLFW key codes, and some codes (all mouse buttons) change, so saved configs need a migration. Frame pacing and click counting use GLFW directly. Text inputs must report focus changes.

## Findings

- **Fail-soft hole, fixed (separate commit).** A required injector whose `@At` matched nothing made Mixin throw an `Error` it treats as fatal: the first 26.1 boot crashed at launch. `InjectionCheck` now reports such mixins after they apply, and `defaultRequire` is 0.
- **MixinExtras applies later.** `@WrapOperation` and the other MixinExtras injectors are applied after Aurora's `postApply`, so `InjectionCheck` saw the armor-trim wrap as unmatched although the exported class (`-Dmixin.debug.export=true`) shows it applied. `InjectionCheck` no longer judges MixinExtras injectors; `check_mixin_targets.py` still covers their target names.
- **Vanilla now paces frames itself.** 26.1's `FramerateLimiter` has an overshoot-smoothed spin wait, much like Aurora's PARK pacer. Under ADR 0005, measure whether Aurora's pacer still improves anything on 26.1 before keeping it on by default.
- The budget's first run is over the limit on both versions (warm-up); `overhead_check.py` drops it.
